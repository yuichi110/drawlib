# 実装プラン：`www.drawlib.com` 全ポータルへの共通上部バナー（`.demo-banner`）導入

## 1. 背景と目的

現在 `https://www.drawlib.com/` 配下でホストされている公式ドキュメント群（User Guide / API Reference / Architecture / Quickstart / About Slide Deck / PNI501 Audit）は、ポータル間の相互ナビゲーションが分断されている箇所があります（特に `/api/` や `/reports/pni-full-audit/`、`/quickstart/`、`/about-drawlib/` からは公式サイト `/` へ戻る導線や他ポータルへのリンクがなく、User Guide `/` からもファーストビューに API Reference や Examples への導線がありません）。

そこで、`fastapi.drawlib.com` や `examples.drawlib.com` と統一されたダークスレート（`#0f172a`）の上部バナー（`.demo-banner`）を **`user_guide`（ルート `/`）を含む全6ポータル** に導入し、以下を実現します。

1. **スイート横断のグローバルナビゲーション**:
   どのポータル・どの階層にいても、1クリックで全ポータル（`User Guide` · `API Reference` · `Architecture` · `Quickstart` · `Slide Deck` · `PNI501 Audit`）および `Examples ↗` (`https://examples.drawlib.com/`)、`GitHub ↗` へ移動できるようにする。
2. **ドッグフーディング（Built with Drawlib）の明示**:
   各ポータル自身が Drawlib のどのプロジェクトアーキタイプ（`type = "site"`, `type = "catalog"`, `type = "doc"`, `type = "slide"`）でビルドされているかを明示する。
3. **成果物（PDF / DOCX / PPTX）への直接アクセス**:
   `quickstart`・`about-drawlib`・`pni-full-audit` では、バナー内に同ロケールの `PDF` / `DOCX` / `PPTX` ダウンロードリンクも併記する。

---

## 2. アーキテクチャ方針（ビルド後 `docs/` への注入方式）

- **重要制約**:
  - `src/drawlib/` 内の組み込みテンプレート（`drawlib init project` で一般ユーザーに配布される HTML/CSS）には**絶対にバナーを入れない**。
  - `docs_src/` 配下のソースを汚さず、またヘッドレス Chromium による PDF / PPTX 出力にバナーが映り込まないよう、**`tools/dcli/docs/builder.py` の `build_docs()` の最終ステップ（HTML・PDF・DOCX・PPTX の全ビルド完了後）で `docs/` 配下の生成済みファイルに対して `tools/dcli/docs/banner.py` から一括注入**する。
  - `docs/reports/pni-full-audit/` のように毎回再生成されないディレクトリや、単一ターゲットビルド（`./dcli docs build site` 等）が存在する場合でも安全に再実行できるよう、**べき等（idempotent：すでに `.demo-banner` があれば最新のものに置換、なければ `<body>` 直後に挿入）** として実装する。

---

## 3. 対象となる `docs/` 配下の6ポータル定義

HTML ファイルの `docs/` からの相対パス（`rel_parts = html_path.relative_to(docs_root).parts`）の先頭ディレクトリによって、以下の6ポータルを自動判別します。

| ポータルID | `docs/` 内のパス判定 | アーキタイプ | 対応言語 | 中央テキスト（EN / JA） |
| :--- | :--- | :--- | :--- | :--- |
| `user_guide` | 上記5つ以外のルート配下 (`docs/index.html`, `docs/en/**`, `docs/ja/**`) | `type = "site"` | `en`, `ja` | **EN**: `Official User Guide (<code>type = "site"</code>) built with Drawlib`<br>**JA**: `Drawlib で構築された公式ユーザーガイド（<code>type = "site"</code>）` |
| `api` | `docs/api/**` | `type = "catalog"` | `en`, `ja` | **EN**: `Official API &amp; CLI Specification (<code>type = "catalog"</code>) built with Drawlib`<br>**JA**: `Drawlib で構築された公式 API・CLI リファレンス（<code>type = "catalog"</code>）` |
| `architecture` | `docs/architecture/**` | `type = "site"` | `en` | **EN**: `Internal Architecture Specification (<code>type = "site"</code>) built with Drawlib` |
| `quickstart` | `docs/quickstart/**` | `type = "doc"` | `en`, `ja` | **EN**: `Quickstart Onboarding Guide (<code>type = "doc"</code>) built with Drawlib`<br>**JA**: `Drawlib で構築されたクイックスタートガイド（<code>type = "doc"</code>）` |
| `about-drawlib` | `docs/about-drawlib/**` | `type = "slide"` | `en`, `ja` | **EN**: `Official Showcase Deck (<code>type = "slide"</code>) built with Drawlib`<br>**JA**: `Drawlib で構築された公式紹介スライド（<code>type = "slide"</code>）` |
| `pni501` | `docs/reports/pni-full-audit/**` | `type = "doc"` | `en` | **EN**: `Software Health Diagnostic Report (<code>type = "doc"</code>) generated by PNI501 &amp; Drawlib` |

## 4. バナー HTML・リンク・CSS・JS の仕様

### 4.1 バナー HTML 構造と除外条件
- `<meta http-equiv="refresh" ...>` を含むリダイレクト用 HTML、および `docs/404.html`（`html_path.name == "404.html"`）には注入しない。
- `<html lang="...">` が `ja` で始まる場合は `is_ja = True`、それ以外は `is_ja = False`。
- `docs/` ルートへの相対プレフィックスは `rel_to_docs = "../" * (len(rel_parts) - 1)` で算出し、全リンクを相対パス（外部リンク除く）で記述することでローカル `drawlib serve docs/ --check` でもリンク検証を通過させる。

```html
    <div class="demo-banner" role="region" aria-label="Portal Navigation">
        <div class="demo-banner-inner">
            <span class="demo-banner-badge">DRAWLIB OFFICIAL</span>
            <span class="demo-banner-text">
                <!-- ポータル・言語に応じたテキスト -->
            </span>
            <span class="demo-banner-links">
                <!-- 現在開いているポータルは <strong>Portal Name</strong>、それ以外は <a href="...">Portal Name</a> -->
                <!-- quickstart / about-drawlib / pni501 の場合は PDF / DOCX / PPTX リンクも追加 -->
                <!-- 末尾に Examples ↗ と GitHub ↗ -->
            </span>
        </div>
    </div>
```

### 4.2 右側ナビゲーションリンク一覧（`.demo-banner-links`）
1. **ポータル切り替えリンク**（現在のポータルと一致する項目は `<strong>{label}</strong>`、他は `<a href="{href}">{label}</a>`）：
   - `User Guide`: `{rel_to_docs}ja/index.html` (`is_ja` 時) / `{rel_to_docs}index.html` (`en` 時)
   - `API Reference`: `{rel_to_docs}api/ja/index.html` (`is_ja` 時) / `{rel_to_docs}api/index.html` (`en` 時)
   - `Architecture`: `{rel_to_docs}architecture/index.html`
   - `Quickstart`: `{rel_to_docs}quickstart/ja/index.html` (`is_ja` 時) / `{rel_to_docs}quickstart/en/index.html` (`en` 時)
   - `Slide Deck`: `{rel_to_docs}about-drawlib/ja/index.html` (`is_ja` 時) / `{rel_to_docs}about-drawlib/en/index.html` (`en` 時)
   - `PNI501 Audit`: `{rel_to_docs}reports/pni-full-audit/index.html`
2. **成果物ダウンロードリンク（該当ポータルのみ、`{rel_to_docs}<portal_dir>/<filename>` で階層差を吸収）**:
   - `quickstart`: `docs/quickstart/quickstart_{lang}.pdf` / `.docx` が存在すれば `{rel_to_docs}quickstart/quickstart_{lang}.pdf` (`PDF`) / `{rel_to_docs}quickstart/quickstart_{lang}.docx` (`DOCX`) を追加
   - `about-drawlib`: `docs/about-drawlib/about-drawlib_{lang}.pdf` / `.pptx` が存在すれば `{rel_to_docs}about-drawlib/about-drawlib_{lang}.pdf` (`PDF`) / `{rel_to_docs}about-drawlib/about-drawlib_{lang}.pptx` (`PPTX`) を追加
   - `pni501`: `docs/reports/pni-full-audit/full_audit.pdf` が存在すれば `{rel_to_docs}reports/pni-full-audit/full_audit.pdf` (`PDF`) を追加
3. **外部リンク**:
   - `Examples ↗`: `<a href="https://examples.drawlib.com/" target="_blank" rel="noopener noreferrer">Examples ↗</a>`
   - `GitHub ↗`: `<a href="https://github.com/yuichi110/drawlib" target="_blank" rel="noopener noreferrer">GitHub ↗</a>`

### 4.3 CSS 注入（`docs/**/style.css`）
`docs/` 配下のすべての `style.css` にスタイルを追記（べき等置換）します。
- `1280×920` ビューポートでも1行（`38px`）に収まるようタイポグラフィと余白を調整し、中幅デスクトップ（`max-width: 1180px`）では `.demo-banner-text` を非表示にして1行を維持。
- `site` および `catalog` アーキタイプの左サイドバー（`.sidebar`）がデスクトップ（`min-width: 769px`）でバナーと重ならないよう、`top: var(--demo-banner-h); height: calc(100vh - var(--demo-banner-h));` を適用。
- モバイル（`max-width: 768px`）では、`.sidebar`（上部固定 60px ヘッダー）を持つページのみ `body:has(.sidebar) .demo-banner { margin-top: 60px; }` を適用。
- `slide` アーキタイプ（`about-drawlib`）では `.presentation-viewport { height: calc(100vh - var(--demo-banner-h, 38px)); }` とし、フルスクリーン時（`:fullscreen`）およびプレゼンターモード（`body.presenter-mode`）では `.demo-banner` を非表示にする。
- 印刷時（`@media print`）は `.demo-banner { display: none !important; }`。

### 4.4 `slide.js` のスケール補正（`docs/about-drawlib/slide.js`）
`about-drawlib` の `slide.js` 内の `updateScale()` にて、16:9 ステージの高さ計算が `window.innerHeight` から `.demo-banner` の高さを差し引き、同時に `--demo-banner-h` CSS 変数も実高さで同期するようにパッチします：

```javascript
    const bannerEl = document.querySelector('.demo-banner');
    const bannerH = (bannerEl && !document.fullscreenElement && !isPresenterMode) ? (bannerEl.offsetHeight || 38) : 0;
    document.documentElement.style.setProperty('--demo-banner-h', `${bannerH}px`);
    const windowHeight = Math.max(100, window.innerHeight - bannerH);
```
あわせて `window.addEventListener('load', updateScale);` と `document.addEventListener('fullscreenchange', updateScale);` を登録します。

## 5. 検証ステップ

1. `./dcli docs build` / バナー注入を実行し、`docs/` 配下の全6ポータル（`/`、`api/`、`architecture/`、`quickstart/`、`about-drawlib/`、`reports/pni-full-audit/`）に `.demo-banner` が注入されることを確認する。
2. `./dcli docs serve site --check`（`uv run drawlib serve docs/ --check`）を実行し、全 HTML ファイルでリンク切れが `0` 件であることを確認する。
3. Playwright（`1280×920`）で以下6ポータルのスクリーンショットを撮影し、視覚レビュー（Stage 3 Review）を行う：
   - `docs/en/index.html`（User Guide — `site`、左サイドバーの上端オフセット確認）
   - `docs/api/en/index.html`（API Reference — `catalog`、左サイドバーの上端オフセット確認）
   - `docs/architecture/en/index.html`（Architecture — `site`）
   - `docs/quickstart/en/index.html`（Quickstart — `doc`、PDF/DOCX リンク確認）
   - `docs/about-drawlib/en/index.html`（About Slide — `slide`、16:9 キャンバスの上下余白確認）
   - `docs/reports/pni-full-audit/index.html`（PNI501 Audit — `doc`、PDF リンク確認）
