ArchitectureGraph: Cloud Topologies & Nested Containers

ArchitectureGraph is a declarative two-level macro/micro coordinate solver purpose-built for cloud infrastructure, VPC topologies, and multi-zone microservice architectures.

Unlike generic DAG solvers that flatten nested groups or scramble boundary boxes, ArchitectureGraph solves coordinates in two hierarchical phases: packing internal nodes and child clusters inside parent containers (Micro Layout), then arranging top-level containers across a 5-zone compass (pos="left" | "center" | "right" | "top" | "bottom") with orthogonal highway routing (Macro Layout). Pair layout = g.get_layout() with ArchitectureDiagram to render official cloud icon cards (GcpIcon, PhosphorIcon) and nested NodeGroup boundaries at the solved coordinates.

1. Core Concepts & Basic Usage

ArchitectureGraph separates cloud layout solving from visual rendering: call layout = g.get_layout() once to compute overlap-free container boxes (c.xy, c.bottom_left, c.local_bottom_left), node centers (n.xy, n.local_xy), and orthogonal routes (e.points), then render in strict back-to-front Z-order (clusters, edges, nodes) or map directly onto ArchitectureDiagram. You can nest multi-tier subnets inside a parent g.group() via parent and order, pin peripheral services across the 5-zone compass (pos="top" | "left" | "center" | "right" | "bottom") with configurable container_sep corridors, and nudge individual nodes post-layout via layout.offset(id, dx, dy) while keeping connected edge ports synchronized:

def draw_step_bar(active_part: int) -> None:
    """Draw top 4-part progress bar (active_part is 1..4)."""
    pill_w = 31.0
    pill_h = 7.4

def make_mapper(
    lay: GraphLayout,
    target_cx: float,
    target_cy: float,
    max_w: float,
    max_h: float,
    fixed_scale: float | None = None,
) -> tuple[float, object]:
    """Build a uniform centering coordinate mapper from GraphLayout to studio sheet."""
    xs = [c.left for c in lay.clusters.values()] + [c.right for c in lay.clusters.values()]
    ys = [c.bottom for c in lay.clusters.values()] + [c.top for c in lay.clusters.values()]
    raw_cx = (min(xs) + max(xs)) / 2.0
    raw_cy = (min(ys) + max(ys)) / 2.0
    sc = fixed_scale if fixed_scale is not None else min(max_w / (max(xs) - min(xs)), max_h / (max(ys) - min(ys)))

    def mp(pt: tuple[float, float]) -> tuple[float, float]:
        return (target_cx + (pt[0] - raw_cx) * sc, target_cy + (pt[1] - raw_cy) * sc)

    return sc, mp

Nested Clusters, 5-Zone Compass Placement & ArchitectureDiagram Mapping

You can organize nodes into single-level or nested two-level containers using g.group() and g.cluster(), or by passing group="..." and subgroup="..." directly on g.node():

  • g.group(id, *, nodes=None, padding=4.0, header_height=3.5, parent=None, order=None, pos=None) -> Cluster: Creates a top-level or parent container (such as a Cloud VPC) that can hold child clusters (parent=id).
  • g.cluster(id, nodes=None, *, padding=4.0, header_height=3.5, parent=None, order=None, pos=None) -> Cluster: Encloses a list of nodes inside a container bounding box with padding on all sides and header_height reserved at the top for a group title.
    • parent: ID of the enclosing parent group (e.g. parent="vpc").
    • order: Integer rank (1, 2, ...) controlling the sequence of sibling tiers inside a parent container.
    • pos: Compass zone ("left", "center", "right", "top", "bottom") for macro placement on the canvas.
  • Inline Node Membership (g.node(id, *, width=None, height=None, group="...", subgroup="...")): During get_layout(), ArchitectureGraph inspects each node's group and subgroup attributes. Any referenced cluster ID that has not been explicitly created via g.group() or g.cluster() is automatically registered, the node is appended to the innermost container, and if both group and subgroup are provided, subgroup.parent is automatically linked to group (subgroup.parent = node.group).
  • Seamless Coordinate Mapping to ArchitectureDiagram:
    • Top-Level NodeGroup: c = layout.clusters["vpc"] → vpc = d.add(NodeGroup("VPC", width=c.width, height=c.height), xy=c.bottom_left)
    • Nested NodeGroup: sub = layout.clusters["tier1"] → t1 = vpc.add(NodeGroup("Tier 1", width=sub.width, height=sub.height), xy=sub.local_bottom_left)
    • Child Node inside a NodeGroup: n = layout.nodes["api"] → t1.add(Node("API", *n.size, icon=...), xy=n.local_xy)
    • Top-Level Node: n = layout.nodes["client"] → d.add(Node("Client", *n.size, icon=...), xy=n.xy)

5. Best Practices

  1. Use pos for Peripheral Zones: Keep the main request pipeline in pos="center" (or pos="left" -> pos="center" -> pos="right") and place cross-cutting concerns like CI/CD, IAM, or Observability in pos="bottom" or pos="top".
  2. Reserve Header Clearance with header_height: When rendering solved clusters as NodeGroup containers in ArchitectureDiagram, pass header_height=4.2 to 4.8 on g.cluster() and g.group() so child cards never collide with top-left group titles.
  3. Use .local_bottom_left and .local_xy Inside Nested Groups: Because ArchitectureDiagram positions child elements relative to their parent NodeGroup's bottom-left corner, always pass xy=cluster.local_bottom_left when adding a nested NodeGroup and xy=node.local_xy when adding a Node to a NodeGroup.
